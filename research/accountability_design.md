# 可验证的条件开启和匿名凭证撤销：扩展设计草案

状态：仅为与现有原型可衔接的设计，**尚未实现、计时、形式化证明或进行独立安全审计**。现有 `Circuit` 仅验证 `D=MiMC(101,s)` 的 CA 凭证、持有者绑定签发收据、任务空值符及区域/时间约束；它目前不具备身份开启和凭证撤销功能。以下不是对现有实验数据的描述，也不是将这些功能作为首创的主张。

## 1. 问题和既有成果

原稿包含满足条件时追责的目标；简单地给报告附加“加密的身份”并不够：恶意持有人可以出示自己的合法凭证，却加密另一个人的身份。必须在同一个零知识关系中证明**被加密的身份标识、CA 签发的身份绑定、原有的凭证秘密，以及报告中持有者绑定的签发收据使用同一个秘密**。开启身份与禁用凭证也是不同动作：有开启不意味着已经实施撤销。

可开启匿名凭证与匿名撤销均有早期研究，如 [Camenisch–Lysyanskaya 2001](https://www.iacr.org/archive/eurocrypt2001/20450093.pdf)、[Camenisch–Lysyanskaya 2002](https://doi.org/10.1007/3-540-45708-9_5)；可验证加密和可验证解密亦有成熟研究，如 [Camenisch–Shoup 2002/2003](https://eprint.iacr.org/2002/161)。这里讨论的是把已有思想接入本项目的具体组合，不是新发明这些密码学原语。

## 2. 定义与注册

令 `G` 为选定、具有素数阶 `q` 的离散对数困难椭圆曲线子群，生成元为 `B`。CA 为注册机构，`s` 为持有者独立、高熵生成且保密的字段元素；原凭证继续为 `sig_CA(D)`，其中 `D=H(101,s)`，`H` 表示域分离的 MiMC。身份标识 `I` 为 CA 为实名账户分配的**非单位元随机群点**（例如随机 `u∈[1,q−1]` 后计算 `I=[u]B`），不是把身份证号直接转为点。CA 保存受保护且一一对应的 `I ↔ 经核验账户 ↔ D` 注册表并防止相互冲突的绑定；调查方需要与 CA 合作或拥有被授权的登记表副本才能将 `I` 解析为现实身份。

在认证注册、确认该账户与 `D` 的绑定后，CA 额外签发 `linkSig = Sign_CA(H(d_link,D,I.x,I.y))`。这个附加凭证与现有 `sig_CA(D)` 使用同一个 `D`，不要求更换现有凭证，但需要新的签发操作。CA 必须检查账户和 `D` 的归属以及唯一性；安全签发通道和必要的持有者知识证明由注册流程提供。CA 能看到 `D` 和 `I`，但若 `s` 确实高熵且秘密保存，知道 `D` 并不直接等于知道 `s`。不把这解释为盲签或对 CA 的完全匿名。

调查方的公钥 `P=[a]B`（`1≤a<q`）由可信配置绑定到密钥版本，私钥 `a` 仅由调查方掌握。`P` 规范解码、在曲线上、非单位元且属于素数阶子群；任何报告者不得自行指定可被其控制的开启公钥。轮换后每份记录保存使用的 `P` 和版本。

## 3. 提交的密码关系

每次提交重新独立采样 `r∈[1,q−1]`，计算椭圆曲线 ElGamal 密文：

```text
C1 = [r]B
C2 = I + [r]P
```

以现有 `RegionCircuit`（或无区域树的 `Circuit`）为基础，将 `P,C1,C2` 加入公开输入；将 `I,r,linkSig` 加入私有 witness。扩展电路在原有证明之外增加：

```text
D = H(101,s)
Verify_CA(sig_CA, D) = true                     // 原凭证，同一个 s
Verify_CA(linkSig, H(d_link,D,I.x,I.y)) = true  // 同一个 D 与登记 I 绑定
C1 = [r]B  且  C2 = I + [r]P                   // 证明加密的就是 I
I ∈ G\{O}, 1 ≤ r < q                          // 包括规范范围与子群检查
holder = H(d_holder,s,Context)                 // 原有收据，仍是同一个 s
Verify_Issuer(receipt,H(d_receipt,Context,holder,event)) = true
```

同时保留原有任务 nullifier、时间/空间范围与可选区域 Merkle 关系。验证端从可信配置重建 `P`、任务及区域，从收到的字节重建 `Context`，验证完整证明并记下 `C1,C2`；不得接受报告者提供的可替换信任锚或密钥版本。`P,C1,C2` 是证明的公开输入，因此被绑定到该证明；实际报文和挑战仍由原 `Context` 绑定。若一个恶意账户把别人可开启的 `I'` 放入密文，既不能把它与本人的 `D` 对应的 CA 绑定证书匹配，也不能仅凭上传的密文绕过证明，除非能伪造签名、破坏关系健全性或滥用注册机构。

普通密文仅保证（在相应假设下的）保密；**上面整个电路等式和同一 `D` 才是可验证绑定**。群 ElGamal 本身具有可塑性且一般只提供 IND-CPA，不应宣称 IND-CCA。调查方不可向任意方提供无约束的解密 oracle；开启工作流只处理被验证且获授权的完整提交记录。如何在组合中实现更强的抗选择密文、无诬陷（non-frameability）和可追责安全，仍需形式化建模和审计。

## 4. 开启与可复核的开启

按外部规则核验授权后，调查方检查原提交证明和记录，再用密钥版本对应的 `a` 计算 `I=C2−[a]C1`，在受保护注册表中查询相应账户。调查方若需让获授权的复核者独立验证解密正确，可附加一个 Chaum–Pedersen 等离散对数证明：

```text
log_B(P) = log_C1(C2−I)
```

将提交证明摘要、`Context`、任务、密钥版本、密文、调查决定和协议版本编码进 Fiat–Shamir 挑战，复核者验证证明与原记录绑定。开启结果和证据只向有权限的对象披露；公开 `I` 会使相同 `I` 的开启记录可链接。授权策略、审批、防泄漏审计和机构问责不是此电路能自行保证的，门限开启需要另行设计和实现；单一 `a` 持有人在密码学上始终可以解密，不应将行政审批写成密码学阈值保证。注册表的真实性和现实身份核验仍依赖 CA，开启意味着**登记凭证**归属，不自动证明当时驾驶者或传感物理事实。

## 5. 匿名撤销的具体可实现扩展

令 `L=H(d_active,D)`，由知道登记 `D` 的 CA 生成并加入活跃凭证集合；以有序或固定索引的 Merkle 树生成经认证根 `R_active`。新增证明中，持有者用原秘密算出相同 `D` 与 `L`，在电路内私有证明 `L` 对 `R_active` 的成员路径。公开输入中加入受信任且当前的 `R_active`、epoch 和策略版本；验证方从可信渠道取得，不取自报告者。签发收据、空值符、原 credential、identity link 和活跃叶全部通过同一个 `s`/`D` 连接。

撤销时 CA 根据登记表将该凭证叶移除或置为 inactive，发布带完整版本信息和签名的新根；验证方必须拒绝过期或回滚的根并在接受时确定当前策略，持有人则需更新路径。生效时刻、并发提交期间根更新的原子性、故障恢复、可信时间、根分发和路径更新均需要实现规则。对于重复入册或同一主体持有多个凭证，仅撤销一个叶不能自动撤销其他凭证。已接受报告不会因后续撤销自动失效；历史审计应保留当时生效的根。仅声明短期证书或黑名单而不实施上述校验，不能说已支持动态撤销。

活跃集合根、叶变化、更新时机、网络流量和 CA 的登记表可能带来侧信道或相关性；匿名证明不自动隐藏所有元数据，也不覆盖 CA、调查方和网络观察者串谋的情况。叶 `L` 是由高熵秘密派生的散列，不应加入真实身份、车牌等可枚举明文。长期持有固定叶可能泄露集合更新层面的信息，应根据威胁模型设计批处理或其他现有匿名撤销机制。

## 6. 实施成本、测试与未解决事项

相对现有区域原型，理论增量包含一次电路内 EdDSA 绑定证书验证、两次同一 `r` 的曲线标量乘法、点加法及输入/点/子群检查；开启公钥可固定以避免报告者选择。撤销还需一次叶哈希和深度 `d` 的 Merkle 路径计算、可信根更新与身份注册记录。开启密文增加两个群点（外部压缩编码格式和电路公开坐标编码应分别统计）；Groth16 证明的大小是否保持现有 164 B 需以实际序列化验证，公开 witness 变大。当前没有上述功能的耗时、约束数、通信及存储实测，不能给出数值或称其轻量。

优先测试：合法开启/查表；不同随机数下同一账户的密文不同；替换 `I`、`C1`、`C2`、`P`、密钥版本、任务或签发收据时拒绝；使用他人 linkSig 或低阶/畸形点、`r=0` 和越界标量时拒绝；同一 `s` 正常通过活跃根且撤销新根后拒绝、旧根不可回滚；开启证明与登记记录篡改被拒绝。分开测量注册、开启、根更新和新电路的 30 次证明与验证。对抗性求解器/恶意 hint 必须纳入检查，普通诚实 prover 的失败测试不足以证明健全性。

实现前还要核对已固定的 gnark 版本：项目为 `v0.14.0`，[官方 2026 安全公告](https://github.com/Consensys/gnark/security/advisories/GHSA-3mvx-pp85-pm65) 对 `<v0.16.2` 的若干 gadget 列出健全性问题；公告未直接点名当前 native twisted-Edwards 关系，不能因此断言当前原型已受影响，但也不能把现有测试当成安全审计。新增曲线乘法时尤其需要检查 hint、零值、子群和非规范编码，必要时改用经过审查的算法或升级后重做全部实验。组合式零知识/匿名性/可追责定理、CCA 安全、门限开启、可信注册、设备保密、抗中继及真实传感数据真实性都尚未完成或不在该关系保证范围内。
